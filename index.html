Что нужно перед запуском

Три шага настройки

Скилл требует Claude Code с Firecrawl MCP и установленного плагина pain-driven-research. Один раз настроил — запускаешь для любой ниши.

1
Установи Claude Code + Firecrawl MCP
Claude Code (CLI): npm install -g @anthropic-ai/claude-code
Firecrawl MCP для скрейпинга: добавь в ~/.claude/settings.json под ключом mcpServers. Нужен API-ключ Firecrawl — получи на firecrawl.dev.
2
Установи скилл competitive-intel-to-html
Положи файл SKILL.md в папку ~/.claude/skills/competitive-intel-to-html/. При следующем запуске Claude Code скилл появится в реестре автоматически.

Также нужен субскилл pain-driven-research в ~/.claude/skills/pain-driven-research/.
3
Подготовь входные данные для своей ниши
Минимум: ключевое слово ниши + гео (город или «РФ»).
Опционально: URL бренда клиента, дизайн-токены (#HEX акцента, шрифты), путь к утверждённому копирайту клиента.
Пошаговый процесс

9 фаз: от запроса
до готового пакета

Каждая фаза производит один артефакт. Артефакты связаны по цепочке — каждый следующий строится на предыдущем. Не прыгай через фазы.

01
SERP Discovery — найти реальное конкурентное поле

Никогда не угадывай конкурентов. Используй Firecrawl search по 3-5 коммерческим запросам и ранжируй домены по частоте появления.

Запросы: «купить {ниша} {город}», «{ниша} цена», «{ниша} отзывы», «{ниша} производитель», «{ниша} оптом» (для B2B)
Сохрани: domain, appearances (сколько раз встретился), intent_bucket, serp_rank, type (producer/dealer)
Выбери топ-5–7 доменов для глубокого анализа
📄 01-serp.json
02
Scrape сайтов — зафиксировать что и как говорит каждый конкурент

Firecrawl scrape каждого домена из топа. Один файл на домен — никаких комбинированных отчётов.

Записывай: H1, hero copy, CTA текст, видимость цены или «по запросу»
Фиксируй trust-элементы: сертификаты, лет на рынке, количество отзывов, фото производства
Визуальный стиль: цвет акцента (hex), типографика, плотность, ощущение на мобильном
Маркетплейсы не конкуренты — только визуальные референсы, не стратегические якоря
📁 02-sites/<domain>.md
03
Отзывы дословно — язык покупателя = язык сайта

Иди туда, где реальные покупатели жалуются и хвалят: 2GIS, Отзовик, Я.Маркет, ИРекомендую, Форумхаус, Мастерград.

Минимум 15 дословных цитат — без пересказа своими словами
Для каждой цитаты: категория боли, source URL, автор/дата (если публичны)
Категории болей: качество, цена, доставка, страх контрафакта, монтаж, хранение
Слова покупателей идут прямо в тексты сайта — не адаптируй их «под бренд»
📁 03-reviews/<source>.md
04
Скоринг 8×10 — установить кто лидер и почему

Оцени каждого конкурента по 8 критериям от 1 до 10. Максимум 80 баллов. Это таблица, от которой считается «сколько сайт должен набрать».

Критерии: видимость в поиске / качество отзывов / дизайн / мобайл / глубина контента / social proof / CTA / скорость
Определи лидера (кто задаёт планку) и слабейшего (кто показывает пол ниши)
Выдели паттерны топ-10%: что делают лидеры, чего не делают аутсайдеры
Сюда ставь потенциальный скор клиента с комментарием «что нужно для него»
📄 04-scoring.md
05
GAP-анализ — 7 бакетов без домыслов

Где конкуренты не закрывают боли покупателей — там деньги. Используй 7-бакетный фреймворк. Правило: ни один GAP без доказательства.

Насыщение — что делают 3+ конкурентов (must-have, но не дифференциатор)
Пробелы — боли, которые никто не закрывает (золото для дифференциации)
Визуальные GAP'ы — UI-паттерны, которых нет ни у кого
Copy GAP'ы — словарь из отзывов, которого нет в чьём-либо копирайте
Trust GAP'ы — доказательства, которых хочет покупатель, но никто не показывает
Ценовые GAP'ы — прозрачность цены
Мобильные GAP'ы — что никто не оптимизирует на мобильном
📄 05-gap-analysis.md
06
Стратегия структуры сайта — мост между исследованием и реализацией Ключевая фаза

Эта фаза обязательна. Без неё wireframe — угадайка, а не стратегия. Цель: определить сайт как воронку решения покупателя, а не набор блоков.

Для каждой секции заполни 6 полей: секция / задача покупателя / боль или возражение / доказательство / почему здесь / роль в конверсии
Роли: attention → trust → education → proof → action
Рекомендованная последовательность: Hero → Быстрый trust → Признание боли → Механизм → Сравнение → Доказательная стена → Доставка/условия → FAQ → Final CTA
Если нужно: гибрид маркетплейс-карточка сверху (ясность продукта) + лендинг снизу (убеждение)
Wireframe не изобретает секции — он визуализирует уже одобренную структуру из этого файла
📄 06-site-structure.md
07
Wireframe — боль × UI-паттерн

Переводит одобренную структуру в конкретные UI-решения. Не абстракции — конкретные паттерны с визуальным бенчмарком.

Каждая секция × 4 атрибута: Функция / Боль (цитата) / Визуальный бенчмарк / Визуальное решение
Бенчмарк: лучший конкурент ИЛИ «GAP — никто не делает»
Визуальное решение: sticky gallery, drag-compare slider, marquee, specs table, proof wall — не «красивая карточка»
📄 07-wireframe.md
08
Тексты — только язык покупателя, только с доказательствами

Пишем только для секций, у которых ещё нет утверждённого текста клиента. Язык берём из 03-reviews/.

Использовать реальный словарь покупателей из отзывов
Называть конкретный механизм: «аминные отвердители», а не «специальная защита»
Запрещены флафф-прилагательные без числа: «прочный», «качественный», «надёжный» сами по себе
Каждый сильный claim = число или сравнение с конкурентом
Для каждой секции: заголовок + поддержка + proof bullets + CTA (если есть)
📄 08-copy.md
09
HTML-отчёт — стратегия-продающий документ для клиента

Self-contained HTML без JS-бандла. Открывается в браузере без сервера. Это не дамп данных — это документ, который продаёт стратегию.

Обязательные секции: Executive Summary / Профили конкурентов / Сравнительная таблица / Боли дословно / Нишевая палитра / GAP-анализ / Структура сайта / Паттерны топ-10% / Методология
Дизайн: бумажный фон #F5F0E8, тёмные заголовки Instrument Serif, акцент бренда клиента, grain overlay
Cover page: тёмный фон + оранжевый radial glow + дата + счётчики источников
Никакого внешнего JS — только Google Fonts @import
📄 09-competitive-report.html
Как запустить

Одна фраза — весь пайплайн

Скажи агенту что хочешь и по какой нише. Claude Code определит скилл и запустит все 9 фаз. Или используй готовый промпт ниже.

// Фразы-триггеры
«Разведка рынка по нише [ниша] в [город]»
«Сделай competitive research для лендинга»
«Сайт по болям клиентов — [ниша]»
Любая из этих фраз активирует скилл competitive-intel-to-html автоматически.
// Готовый промпт — скопируй и замени значения
Запусти скилл competitive-intel-to-html для ниши: Ниша: [ВАША НИША, например «стеклопластиковая сетка»] Гео: [ГОРОД или «РФ»] Папка вывода: ./research/competitors/ URL бренда клиента: [URL или «нет»] Акцентный цвет: [#HEX или «по нише»] Запускай фазы по порядку. После каждой — сохраняй артефакт. В конце собери HTML-отчёт.

Типичные ошибки

Что идёт не так — и как фиксить

Самые частые ошибки при первом запуске.

❌ Ошибка
Остановился на GAP-анализе, не дошёл до структуры сайта
✓ Как надо
Скилл готов только когда есть 06-site-structure.md — мост между исследованием и реализацией
❌ Ошибка
Пересказал отзывы покупателей своими словами «в стиле бренда»
✓ Как надо
Только дословные цитаты. Слова покупателя идут прямо в заголовки и буллеты сайта
❌ Ошибка
Прыгнул из GAP прямо в wireframe, пропустив фазу 06
✓ Как надо
Фаза 06 (site-structure) обязательна. Wireframe визуализирует одобренную структуру, не изобретает её
❌ Ошибка
HTML-отчёт — дамп данных со скучными таблицами
✓ Как надо
Отчёт — стратегия-продающий документ. Он должен убеждать клиента, не просто информировать
❌ Ошибка
GAP без доказательства («кажется, никто не делает X»)
✓ Как надо
Каждый GAP = цитата из отзыва ИЛИ наблюдение из фаз 2-3. Нет доказательства — нет GAP'а
❌ Ошибка
Угадал конкурентов вместо SERP-поиска («все знают что это arm-plast.ru»)
✓ Как надо
Всегда начинай с Firecrawl search. Реальный SERP часто удивляет — дилеры и агрегаторы бьют производителей
